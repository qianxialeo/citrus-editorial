## 发帖与交流

注册并完成邮箱验证后即可发言，不额外要求线下身份核验。支持保存草稿、编辑本人帖子、撤回帖子，以及编辑或删除本人评论；实际修改内容后显示最近修改时间。内容修改可能需要重新审核。

- 作品讨论板中的帖子围绕特定作品展开。欢迎认真分析，也欢迎适度玩梗。
- 涉及关键剧情时，请在标题或正文开头说明剧透范围，并使用网站提供的剧透标记。
- 可以批评作品和观点，不攻击发言者；不要刷屏、反复玩低质量烂梗，或发表以恶意拆解百合关系、挑衅同好为目的的“百破”言论。正常的作品批评和剧情分析不因涉及争议自动视为违规。
- 引用台词、资料或使用图片时注明来源，并确认具备必要的使用许可。
- 标签使用 `#标签`，多个标签以空格分隔。可通过标签检索相关帖子。

### 图片

帖子正文与封面合计最多9张不同图片，同一张图片兼作封面和插图时只计一次。支持静态 PNG、JPEG、WebP，单张原文件不超过6MB；回复最多3张图片。

连续放置、仅以空白分隔的多张图片会显示为可左右切换的图组；图片之间有正文时，保留在对应段落位置。点击图片可查看大图。

图片管理区可以插入或移除图片。暂存图可以直接删除；原帖图片先从当前编辑稿移出，保存后才改变帖子。刷新后可恢复本人暂存图片，未插入的暂存图不会自动发布。

## 审核与反馈

网站支持词表提示、AI辅助审核和人工复审。是否启用自动通过、图片审核及可信成员回复先发后审，以后台当前设置和页面说明为准。AI存疑、调用失败或超时时转人工，编辑部仍可复审并撤下内容。

使用AI审核前，页面会说明处理方式并征求相应授权。不要将模型判断当作绝对结论；对审核结果有异议，可以通过网站反馈渠道联系编辑部。

GitHub Issue 用于报告网站功能、排版问题和改进建议。请说明页面位置、复现步骤、实际表现、期望表现、设备及浏览器，必要时附经过遮挡的截图。一条 Issue 尽量只记录一个问题，遇到相同问题优先在原记录补充。

账号申诉、内容举报、版权反馈及涉及个人资料的问题，应通过网站内对应入口或编辑部联系渠道处理。不要把密码、API密钥、Cookie、`.env`、成员个人信息或服务器凭据贴到 Issue 中。

## 设计与维护

整体风格以简洁、清晰、偏文艺为主，参考色为茉莉绿 `#ACD38B` 与橘色 `#FFAD42`。讨论区采用原创界面，不使用其他游戏或社区的标识、专有字体及美术素材。

当前网站采用 Next.js、TypeScript 与 SQLite。修改前保留数据库、上传文件和原有密钥的备份，更新时不覆盖线上配置或清空成员数据。网站美术、刊物内容和第三方作品图片的授权分别处理；公开项目介绍不代表这些内容可以自由转载或商用。
